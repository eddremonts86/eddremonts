# Deployment

El portfolio se deploya como sitio estático en **Netlify**.

---

## Pipeline de build

```
pnpm build
    │
    ├── 1. tsc -b          # TypeScript check (strict)
    │      Si hay errores → BUILD FALLA
    │
    └── 2. vite build       # Bundle con Rollup
           ├── Tree shaking
           ├── Code splitting (React.lazy chunks)
           ├── CSS purging (Tailwind)
           ├── Minificación
           └── Sitemap generation (vite-plugin-sitemap)
           
Output: dist/
```

---

## Configuración de Netlify

**Archivo**: `netlify.toml` (en la raíz del workspace)

```toml
[build]
  base = "edd-portfolio"
  command = "pnpm build"
  publish = "dist"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

### Campos clave

| Campo | Valor | Función |
|-------|-------|---------|
| `base` | `edd-portfolio` | Directorio del proyecto dentro del monorepo |
| `command` | `pnpm build` | Comando de build |
| `publish` | `dist` | Directorio de salida |
| `redirects` | `/* → /index.html` 200 | SPA catch-all — todas las rutas sirven `index.html` |

### Fallback SPA

El redirect catch-all también está duplicado en `public/_redirects` para redundancia:

```
/*    /index.html   200
```

## Troubleshooting

### Build falla con errores de TypeScript

```bash
# Ver errores específicos
npx tsc --noEmit
```

TypeScript está en modo `strict`. Los errores comunes incluyen:
- Tipos faltantes en datos nuevos de `cvData.ts`
- Props incorrectas en componentes
- Variables no utilizadas

### Build falla con errores de Vite

```bash
# Build con más verbose
npx vite build --debug
```

### Assets no encontrados

Verificar que los archivos están en `public/` (no en `src/`). Los archivos en `public/` se copian tal cual a `dist/`.

### Code splitting no funciona

Verificar que `React.lazy()` usa dynamic import:

```tsx
// ✅ Correcto — genera chunk separado
const Component = lazy(() => import('./Component'));

// ❌ Incorrecto — no genera chunk
import { Component } from './Component';
```
